# CIFAR-10 LeNet 应用（AvgPool）

从解压后的 `clib-sdk` 根目录执行：

```bash
cd apps/lenet
make
```

`make` 编译 `main.cpp`，导出编码需求，调用 ANT 准备材料和编码，执行密文推理，最后解密检查每层输出并打印分类结果。数据已经随应用提供，不需要安装 PyTorch 或重新训练。

**当前配置为 N65536/Q58/P62，保留八次自举，每次输出 Q24。** 本次只修改应用配置和上下文检查，SDK 静态库、公开头和 ANT 工具保持不变。Q58 新生成材料已通过固定样本 0、1、2 的完整密文验收。当前 ANT 的 Q62、DNUM=1 配置在 27-bit 上限下没有足够的互异 P 素数。

## 网络和应用写法

```text
3×32×32
→ Conv(3→6, 5×5) → ReLU → AvgPool(2×2)
→ Conv(6→16, 5×5) → ReLU → AvgPool(2×2)
→ Flatten(400) → FC(400→120) → ReLU
→ FC(120→84) → ReLU → FC(84→10)
```

卷积 stride=1、padding=0；AvgPool stride=2。训练、明文参考和密文应用使用相同的 AvgPool。

完整流程在 `main.cpp` 末尾的 `Main_graph`。本文件中的卷积、池化、全连接和 ReLU 辅助函数都是普通应用代码，内部只调用 `clib.h` 已有的基础 API。没有新增公开算子，也没有把网络实现塞进静态库。

一个密文有 32768 槽。每层张量按连续 NCHW 放在槽位前缀，剩余槽位为零；池化输出重新紧密排列，因此 Flatten 不需要同态运算。卷积、池化、全连接都在应用中生成对角线和边界掩码，以 64 为小步长复用旋转，每层统一 rescale 一次，消耗两个物理 Q limbs。

ReLU 输入先除以校准范围 R，再计算 7/15/13 次 Chebyshev 复合多项式。恢复 R 融合在末段系数与最终线性项中。归一化消耗一个深度，多项式及最终乘法消耗 12 个深度，合计 26 个物理 Q limbs。

Q58 调度如下，共八次自举（四次在 ReLU 前，四次在 ReLU 内）：

| 位置 | 物理 Q limbs |
| --- | --- |
| input → conv1 | 4 → 2 |
| 每次 ReLU 前 | Modswitch 到 2 → Bootstrap 到 24 |
| 归一化 → p7 → p15 | 24 → 22 → 16 → 8 |
| ReLU 内刷新 → p13 → 最终乘法 | Modswitch 到 2 → Bootstrap 到 24 → 16 → 14 |
| pool1 / pool2 | 14 → 12 |
| conv2 / fc1 | 12 → 10 |
| fc2 / fc3 | 14 → 12 |

当前 SDK 自举内部消耗 30 个物理 Q limbs，因此 Q58 最多输出 Q28。本应用仍显式请求 Q24，自举后丢弃多出的 4 个 limbs，沿用已验证的多项式层级安排。中间自举用于恢复可用层级。最终十个 logits 在 Q12。

参数、密钥、编码明文、输入密文和自举上下文全部由 ANT 生成。应用的 `Encode_plain` 在导出模式只保存数值和需求；计算模式加载对应的 ANT 材料。用户不需要手写 JSON、encode.inc 或 param.hh。

## 随应用提供的数据

`data/` 包含五层训练权重和偏置、四个激活范围、固定测试样本 0/1/2 及各层参考。默认运行样本 0。`training.txt` 记录训练和预测信息。

模型使用固定 seed=0，CIFAR-10 原训练集划分为 45,000 张训练、5,000 张验证；训练 30 个 epoch，batch=128，Adam，学习率从 1e-3 余弦下降至 1e-5，训练增强为随机裁剪和水平翻转。输入逐通道统一归一化为 `(pixel/255 - 0.5)/0.5`。依据验证集选择第 26 个 epoch 的权重，完整 10,000 张测试集准确率为 **62.26%**。

激活范围仅用训练划分中的固定 256 张图逐层校准，前置激活使用同一多项式。范围取 `1.25×最大绝对值` 向上到二的幂，得到 **8、16、16、16**。测试样本超出校准范围会报错。

固定样本 0、1、2 的原始网络与多项式网络预测分别为 5、1、8，真实标签为 3、8、8；前两张分类不正确，仍用于数值验证，没有根据预测结果挑选样本。

## 检查和结果

不生成密钥，只验证普通数值的布局、卷积边界和分组旋转公式：

```bash
make build
.build/app --check-packing
```

该检查使用独立的空间卷积参考，覆盖真实输入、通道变化输入、角点输入、池化紧密排列、全连接和零尾部。ReLU 的独立代数和深度检查在维护者工具中完成。

密文验收要求每层及八次自举输出的全部 32768 槽与多项式参考比较，最大绝对误差不超过 1e-3。最终预测还需与多项式网络、原始 PyTorch 网络一致。多项式近似误差与 FHE 数值误差分别报告；真实标签不参与数值 PASS 判定。

运行结果位于 `result/`：`verification.json` 为逐层误差，`stages.csv` 为阶段耗时，`breakdown.csv` 为 API 耗时分解。时间单位为秒，阶段耗时不包括离线材料生成和编码。

## 本次实测结果（Q58/P62）

三个固定样本全部通过。每份运行检查 19 组输出，每组全部 32768 槽（包括零尾部），统一绝对误差阈值为 1e-3；共 57 组输出、1,867,776 个槽位比较。全部八次自举输出均单独检查。

| 样本 | 真实标签 | 密文 / 多项式 / 原始网络 top-1 | 全阶段最大误差 | logits 最大 FHE 误差 |
| --- | ---: | --- | ---: | ---: |
| 0 | 3 | 5 / 5 / 5 | 0.00012014076 | 5.1697868e-05 |
| 1 | 8 | 1 / 1 / 1 | 0.00023232336 | 0.00023232336 |
| 2 | 8 | 8 / 8 / 8 | 8.3788e-05 | 7.8114759e-05 |

类别 3 为猫，5 为狗，8 为船，1 为汽车。样本 0、1 在原始网络中同样预测错误，仍保留为数值验收样本，没有挑选预测正确的输入。

原始 ReLU 网络与多项式网络的 logits 最大差异，三个样本分别为 0.0307438、0.0425744、0.0539117。这是激活近似误差，与上表的 FHE 计算误差分别记录。

本次重新生成 Q58 参数、密钥、自举材料、应用明文和输入密文。样本 1、2 与样本 0 共用一套上下文，权重声明及原始数值逐字节核对一致后复用编码；输入分别由 ANT 加密。不重抽密钥，不改变阈值，不替换输入。

本次 CPU 运行实测 OpenMP 为 32 线程。三个验收进程相互重叠，以下是本次墙钟耗时，不是独占机器的性能基准，也不能据此直接比较 Q54 与 Q58 的速度。样本 0 的阶段耗时如下：

三个样本的网络总时间分别为 2975.46、2869.07、2916.21 秒。样本 0 自举占网络总时间约 54.3%。各次自举、各段多项式和全部 API 分解见 `result/stages.csv`、`result/breakdown.csv`；线程实测见 `result/runtime.csv`。

首次 ANT 上下文准备约 1292.51 秒（21.5 分钟）；首次完整 `make` 包括编译、导出、上下文准备、编码、加载、计算与解密验证，共 90 分 31 秒。后续 `make` 会复用未改变的上下文和编码，重新计算与验证。

样本 0 的工作材料与结果约 94.1 GiB，其中上下文约 33.3 GiB、应用编码约 59.7 GiB。首次完整流程的进程峰值内存约 44.9 GiB。发布 ZIP 仅包含原始权重、固定输入和参考，不包含这些生成材料或私钥。

SDK 静态库、`clib.h`、ANT 二进制工具和构建标识均与切换前逐字节一致。本次只改应用参数、上下文检查、验收运行参数和说明文档。历史 Q54 的结果见 [验证记录](../../docs/VALIDATION.md)。
