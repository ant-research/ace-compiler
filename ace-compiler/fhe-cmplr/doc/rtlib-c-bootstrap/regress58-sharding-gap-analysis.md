# regress58 resnet18-conv2d sharding gap analysis (C OpenFHE backend)

Read-only investigation of a non-passing regress58 operator case on the C-side
OpenFHE backend: a `:sharding` resnet18 conv (optset `-VEC:ms=4096:sharding
-CKKS:q0=60:sf=59:N=8192`). The recorded symptom is a CRASH. This document
answers the six questions posed, with file:line evidence, the crash mechanism,
the df-on vs df-off comparison, and a concrete fix design (described only --
source code was not modified in this investigation).

All paths below refer to source-tree files (relative to the fhe-cmplr source
tree) or to generated-graph artifacts referenced by role, not by machine-local
tempdir location.

## 1. Exact situation (crash, single Prepare_input call, k shards)

### Crash signature (from the run log)

The run log records an OpenFHE exception of the form:

```
terminate called after throwing an instance of 'lbcrypto::OpenFHEException'
  what():  MakeCKKSPackedPlaintextInternal(): The size of the vector with values
should not be greater than ringDim/2 if the scheme is CKKS
```

The harness classifies this as a CRASH (SIGABRT). The throw site is
`OPENFHE_CONTEXT::Prepare_input` at `rtlib/openfhe/src/openfhe_lib.cxx:66`
(`_ctx->MakeCKKSPackedPlaintext(vec, 1, of_level)`), where `vec` is the full
input tensor and the ring is N=8192 (slots 4096). OpenFHE rejects a vector
larger than ringDim/2 (4096) when the full-tensor size exceeds the slot count.

### (b) main.c calls Prepare_input ONCE with the full tensor

The cti driver `main.c` is generated by `tool/onnx2c.py:339`
(`prepare_input_template = '  Prepare_input(%s, "%s");\n'`) and emits exactly one
call per input. For the resnet18 case:

```
int main(int argc, char* argv[]) {
  Prepare_context();
  ...
  Prepare_input(input_data1, "input");
```

`input_data1` is the full tensor (the `input1[]` literal on the preceding lines
is the full-element array for the input shape). So the backend receives the
whole tensor in a single `Prepare_input` call and is responsible for splitting
it into per-shard ciphertexts.

### (c) the generated graph reads Get_input_data("input", 0..k), k=4 shards

From the generated graph:

```
  for (int input_idx = 0; input_idx < 4; ++input_idx) {
    input_0[input_idx] = Get_input_data("input", input_idx);
  }
```

So **k = 4** distinct indices are read (`0,1,2,3`), declared as
`CIPHERTEXT input_0[4]`.

The shard plan is emitted by `Get_encode_scheme`:

```
int Get_input_count() {
  return 1;                       // one declared input named "input"
}

DATA_SCHEME* Get_encode_scheme(int idx) {
  static MAP_DESC desc_0[] = {
    { NORMAL, 3136, 0, 0, 1},     // {kind, count, start, pad, stride}
    { NORMAL, 3136, 3136, 0, 1},
    { NORMAL, 3136, 6272, 0, 1},
    { NORMAL, 3136, 9408, 0, 1},
  };
  static DATA_SCHEME scheme_0 = {
    "input", {1, 16, 28, 28}, 4, desc_0      // name, shape, _count=4, _desc
  };
  static DATA_SCHEME* scheme[] = { &scheme_0 };
  return scheme[idx];
}
```

Per-shard slot count: each shard carries **3136** values (`MAP_DESC._count =
3136`), far below the 4096 slots available at N=8192. The four shards tile the
flat tensor contiguously (starts 0, 3136, 6272, 9408; stride 1; pad 0):
3136*4 = 12544 = 1*16*28*28. So each shard individually fits in one ciphertext;
only the whole-tensor-into-one-ciphertext encoding overflows.

`MAP_DESC` and `DATA_SCHEME` are defined at `rtlib/include/common/common.h:48-54`
and `:65-70`: `{MAP_KIND _kind; int _count; int _start; int _pad; int _stride;}`
and `{const char* _name; SHAPE _shape; int _count; MAP_DESC* _desc;}`.

## 2. Root cause: openfhe Prepare_input does not shard

`rtlib/openfhe/src/openfhe_lib.cxx:43-70` -- `OPENFHE_CONTEXT::Prepare_input`:

```
  void Prepare_input(TENSOR* input, const char* name) {
    size_t              len = TENSOR_SIZE(input);
    std::vector<double> vec(input->_vals, input->_vals + len);
    CKKS_PARAMS* pp = Get_context_params();
    // ... of_level seam comment ...
    uint32_t of_level = 0;
    if (_bts_ir_capacity > 0 && (size_t)pp->_input_level > 0 &&
        _bts_ir_capacity > (size_t)pp->_input_level) {
      of_level = (uint32_t)(_bts_ir_capacity - (size_t)pp->_input_level);
    }
    Plaintext           pt = _ctx->MakeCKKSPackedPlaintext(vec, 1, of_level);
    Ciphertext*         ct = new Ciphertext;
    *ct                    = _ctx->Encrypt(_kp.publicKey, pt);
    Io_set_input(name, 0, ct);
  }
```

It encodes the **entire** tensor (`len` values) into a single
`MakeCKKSPackedPlaintext` and stores it at **only** `Io_set_input(name, 0, ct)`.
It does not consult `Get_encode_scheme`, does not iterate shards, and does not
fill indices 1..k-1. `Prepare_input_dup` (`:490-492`) delegates to this same
function, so it is equally non-sharding.

The sibling ant backend shards. `rtlib/ant/ckks/src/rtlib.c:164-192`:

```
void Prepare_input(TENSOR* input, const char* name) {
  DATA_SCHEME* scheme = NULL;
  for (int i = 0; i < Get_input_count(); ++i) {
    DATA_SCHEME* ptr = Get_encode_scheme(i);
    IS_TRUE(ptr != NULL, "invalid encode scheme");
    if (strcmp(ptr->_name, name) == 0) { scheme = ptr; break; }
  }
  IS_TRUE(scheme != NULL, "not find the input");
  IS_TRUE(scheme->_count > 0, "no desc found in scheme");
  for (int i = 0; i < scheme->_count; ++i) {
    VALUE_LIST* input_vec = Pre_encode_scheme(input, &scheme->_desc[i]);
    IS_TRUE(input_vec != NULL, "invalid input vector");
    // encode & encrypt
    PLAINTEXT* plain = Alloc_plaintext();
    size_t input_lev = ((CKKS_ENCODER*)Context)->_params->_input_level;
    ENCODE_AT_LEVEL(plain, ...encoder, input_vec, input_lev);
    CIPHER ciph = Alloc_ciphertext();
    Encrypt_msg(ciph, ...encryptor, plain);
    Io_set_input(name, i, ciph);          // per-shard Io_set_input idx i
    Free_value_list(input_vec); Free_plaintext(plain);
  }
}
```

ant finds the matching scheme by name, iterates `scheme->_count` shards,
slices each via `Pre_encode_scheme(input, &scheme->_desc[i])`, encodes each
shard into its own ciphertext, and stores at `Io_set_input(name, i, ciph)` for
i = 0..count-1. The openfhe backend lacks this loop entirely.

The common `Io_init` (`rtlib/common/src/io_lib.c:63-84`) already sizes the
per-name input storage from `Get_encode_scheme(i)->_count`, and
`Io_set_input` (`io_lib.c:29-40`) bounds-checks `idx < _count`; so the Io layer
is shard-ready. The gap is purely in `OPENFHE_CONTEXT::Prepare_input`: it fills
only slot 0 and (in this case) overflows the encoder before even reaching the
Io layer.

## 3. df ON vs df OFF relationship

### df does not change the input path

Regenerating the resnet18 graph both ways (fhe_cmplr in a tempdir; rtlib not
modified):

- df OFF (default): `fhe_cmplr <onnx> -o graph_dfoff.c -VEC:ms=4096:sharding
  -CKKS:q0=60:sf=59:N=8192 -P2C:lib=openfhe`.
- df ON: add `-P2C:df=on` (the offline-dataflow compression noted in the
  reference results: a large character-count graph compresses to roughly
  hundreds of lines).

`Get_encode_scheme` is **identical** between df-off and df-on: the same 4
NORMAL shards, count=3136, starts 0, 3136, 6272, 9408, shape 1x16x28x28.
`Get_input_count()` returns 1 in both. The graph's input-read loop is
identical in both (`input_0[input_idx] = Get_input_data("input", input_idx)`
for idx 0..3). The `bool Need_bts() { return false; }` is also identical
(resnet18 takes the plain levelled-SHE branch, `of_level = 0`).

df-on only changes how constants/weights are materialized: the df-on graph
calls `Pt_from_msg(...)` for each offline-encoded plain instead of inlining
them; the input shard contract is unchanged.

### main.c calls Prepare_input once regardless of df

`tool/onnx2c.py:339` always emits `Prepare_input(%s, "%s");` -- there is no
`Prepare_input_dup` branch in any main scaffold. So df-on does not hand the
backend per-shard tensors or make per-idx calls; main.c still calls
`Prepare_input` once with the full tensor.

### df-on does not build on the OpenFHE backend

Building df-on on `--lib openfhe` fails at graph COMPILE, before any run,
because `Pt_from_msg` is undeclared:

```
error: 'Pt_from_msg' was not declared in this scope
fhe_build_openfhe: g++ compile of graph FAILED ... (dfon)
```

`Pt_from_msg` is an ant/phantom offline-encoding primitive. It is implemented
at `rtlib/ant/porting/pt_mgr.c:188` (and `rtlib/phantom/src/pt_mgr.cu:195`),
declared in `rtlib/include/common/pt_mgr.h:47`, but the OpenFHE backend does
not declare or implement it:
`rtlib/include/rt_openfhe/openfhe_api.h` exports only the `Openfhe_*`
functions and has no `Pt_from_msg`/`load_data_entry` symbol. So df-on is not a
runnable configuration for the OpenFHE backend today; it cannot reach
`Prepare_input` at all.

### ant passes df-off (reference)

The C ant backend passes the same case with df off (built via
`tool/fhe_build.sh` with the same optset, no `-P2C:lib=` so it targets
rt_ant). The run result is a SUCCESS with bounded absolute error, matching
the documented reference. ant's `Prepare_input` is the sharding code in
section 2 above.

### df verdict

- df-on does not PASS on OpenFHE -- it does not even build (`Pt_from_msg`
  undefined). It is not a workaround.
- df-off crashes on OpenFHE at `Prepare_input` (the sharding gap).
- ant passes df-off (and df-on) because its `Prepare_input` shards via
  `Get_encode_scheme`.
- The crash is therefore **not df-specific in the "df-on fixes it" sense**.
  The df-off path crashes for lack of sharding; the df-on path is a separate,
  currently-unbuildable OpenFHE gap (offline-encoding primitive not provided).
  The proper fix is the `Prepare_input` sharding edit (section 5), which fixes
  the df-off catalog path that regress58 actually exercises.

## 4. Can it be fixed: yes

Yes. This is a missing backend feature (sharded/large-input encoding that
honors the emitted `Get_encode_scheme` plan), not a CKKS precision or
algorithm limit. The ant C backend runs the identical case (real CKKS, same
optset, same graph shard plan) and produces a correct result via exactly the
`Get_encode_scheme`-driven slice/encode/Io_set_input loop quoted in section 2.
The Python rt_openfhe also runs real CKKS over this case and matches. The
OpenFHE backend simply never grew the loop.

## 5. Fix design (describe only; not applied)

### Goal

Rewrite `OPENFHE_CONTEXT::Prepare_input` in
`rtlib/openfhe/src/openfhe_lib.cxx:43-70` to mirror ant's
`rtlib/ant/ckks/src/rtlib.c:164-192`: find the matching `DATA_SCHEME` by name,
iterate its `scheme->_count` shards, slice the input tensor per each
`MAP_DESC`, encode each shard into its own ciphertext at the same input-seam
`of_level` the current single-ct path computes, and store at
`Io_set_input(name, i, ct)` for i = 0 .. scheme->_count-1.

### Existing helpers to reuse (no new deps)

`openfhe_lib.cxx` already includes `common/common.h`, `common/rt_api.h`,
`common/io_api.h`, so all of the following are visible:
- `Get_encode_scheme(int idx)` -- weak, generated graph
  (`rtlib/include/common/rt_api.h:85`).
- `Get_input_count()` -- weak, generated graph
  (`rtlib/include/common/rt_api.h:64`).
- `Get_context_params()` -- weak, generated graph
  (`rtlib/include/common/rt_api.h:48`).
- `Io_set_input(name, idx, ct)` (common, `io_lib.c:102`).
- `DATA_SCHEME`/`MAP_DESC`/`MAP_KIND` (`common/common.h:48-70`); `NORMAL` is
  the only kind ant handles in this path.
- `TENSOR_SIZE`, `TENSOR_VAL(t, idx)` (`rtlib/include/common/tensor.h:32,37`).
  `input->_vals` is the flat double array (already used at openfhe_lib.cxx:46).

No `Pt_from_msg`/`Pre_encode_scheme`/`VALUE_LIST` dependency is needed: the
slice is a plain window over `input->_vals`, reimplemented inline (the ant
`Pre_encode_scheme` slice logic for NORMAL is small and self-contained).

### Slice logic to mirror (ant `Pre_encode_scheme`, rtlib.c:67-110)

For a `MAP_DESC d = scheme->_desc[j]`:
- if `d._count == 0`: take the WHOLE tensor (`TENSOR_SIZE` elements) -- the ant
  whole-image branch (rtlib.c:69-77). This is what the current openfhe code
  does, and what the passing single-shard cases use.
- else (`d._count > 0`, ant slice branch rtlib.c:79-108; asserts `_kind ==
  NORMAL` and `_stride == 1`): the shard vector is `d._count + 2*d._pad`
  doubles,
  - for i in [0, d._count): vec[_pad + i] = input->_vals[d._start + i*d._stride];
  - for i in [0, d._pad): leading pad = 0 if `d._start` lies at a channel
    boundary (`(d._start % (H*W)) == 0`), else `input->_vals[d._start -
    (d._pad - i)*d._stride]`; trailing pad symmetric. (For the resnet18 case
    all shards have `_pad = 0`, `_stride = 1`, so this degenerates to a
    contiguous window `input->_vals[d._start .. d._start + d._count - 1]` --
    3136 doubles per shard.)

### Exact location of the seam level

Keep the existing `of_level` computation unchanged; compute it once and reuse
for every shard. resnet18 takes `Need_bts() == false` so the plain branch runs:
`_bts_ir_capacity == 0` and the guard at openfhe_lib.cxx:62-65 yields
`of_level = 0` (chain top, GL 0). The bootstrap-branch case
(`_bts_ir_capacity > 0 && input_level > 0`) keeps
`of_level = _bts_ir_capacity - pp->_input_level`. Either way every shard of
the same input shares one `of_level`; do not recompute per shard.

### Pseudocode (replaces openfhe_lib.cxx:43-70)

```
void Prepare_input(TENSOR* input, const char* name) {
  CKKS_PARAMS* pp = Get_context_params();
  // seam level (unchanged from the current single-ct path)
  uint32_t of_level = 0;
  if (_bts_ir_capacity > 0 && (size_t)pp->_input_level > 0 &&
      _bts_ir_capacity > (size_t)pp->_input_level) {
    of_level = (uint32_t)(_bts_ir_capacity - (size_t)pp->_input_level);
  }

  // find the matching DATA_SCHEME by name (mirror ant rtlib.c:165-173)
  DATA_SCHEME* scheme = nullptr;
  for (int i = 0; i < Get_input_count(); ++i) {
    DATA_SCHEME* s = Get_encode_scheme(i);
    IS_TRUE(s != nullptr, "invalid encode scheme");
    if (strcmp(s->_name, name) == 0) { scheme = s; break; }
  }
  IS_TRUE(scheme != nullptr, "not find the input");
  IS_TRUE(scheme->_count > 0, "no desc found in scheme");

  size_t H = scheme->_shape._h, W = scheme->_shape._w;  // for pad-boundary test
  size_t total = TENSOR_SIZE(input);                    // whole-tensor branch

  for (int j = 0; j < scheme->_count; ++j) {
    const MAP_DESC& d = scheme->_desc[j];
    std::vector<double> vec;
    if (d._count == 0) {                                 // whole-image shard
      vec.assign(input->_vals, input->_vals + total);
    } else {                                              // NORMAL slice shard
      IS_TRUE(d._kind == NORMAL, "TODO: non-NORMAL input shard");
      IS_TRUE(d._stride == 1, "TODO: non-unit stride input shard");
      IS_TRUE((size_t)d._start + (size_t)d._count * d._stride <= total,
              "input shard out of tensor bound");
      size_t loc = (size_t)d._start;
      bool begin_chan = (H*W && (loc % (H*W)) == 0);
      bool end_chan   = (H*W && ((loc + (size_t)d._count*d._stride) % (H*W)) == 0);
      vec.resize((size_t)d._count + 2*(size_t)d._pad);
      for (int i = 0; i < d._pad; ++i)            // leading pad
        vec[i] = begin_chan ? 0.0
                 : input->_vals[loc - ((size_t)d._pad - i)*d._stride];
      for (int i = 0; i < d._count; ++i) {        // body
        vec[d->_pad + i] = input->_vals[loc];
        loc += d->_stride;
      }
      for (int i = 0; i < d._pad; ++i)            // trailing pad
        vec[(size_t)d._pad + d._count + i] =
          end_chan ? 0.0 : input->_vals[loc + (size_t)i*d._stride];
    }
    Plaintext   pt = _ctx->MakeCKKSPackedPlaintext(vec, 1, of_level);
    Ciphertext* ct = new Ciphertext;
    *ct = _ctx->Encrypt(_kp.publicKey, pt);
    Io_set_input(name, (size_t)j, ct);            // per-shard idx 0..count-1
  }
}
```

`Prepare_input_dup` (`:490-492`) can stay delegating to this `Prepare_input`
(it now shards too), matching ant where `Prepare_input_dup`
(`rtlib.c:134-162`) differs only by using `Pre_encode_scheme_dup` (which
itself differs only by a power-of-two slot padding -- not load-bearing for
the OpenFHE `MakeCKKSPackedPlaintext` path, which zero-pads to the ring
dimension itself).

### Edge cases

- `:sharding` conv reads 4 shards at N=8192 (slots 4096); each shard is 3136
  NORMAL values (pad 0, stride 1) -> a contiguous window. The pseudocode's
  slice branch reduces to `vec = input->_vals[start .. start+3135]` for each.
- Non-NORMAL `MAP_KIND` (CONV/CHANNEL/DIAGONAL): ant `Pre_encode_scheme`
  itself asserts `IS_TRUE(desc->_kind == NORMAL, "TODO: other kind")`
  (rtlib.c:85); none of the regress58 cases use a non-NORMAL input shard, so
  the same guard is fine.
- `_stride != 1`: ant asserts `IS_TRUE(desc->_stride == 1, "TODO: other
  stride")` (rtlib.c:86); same guard is fine for the input path.
- `pad > 0`: channel-boundary zero vs extended-value pad is implemented per
  ant rtlib.c:44-62 (the `begin_channel`/`end_channel` test). For the resnet18
  case pad is 0, so this path is inert here; it is included for faithfulness
  to the ant contract so future sharded inputs with halo padding work too.
- `Encode_float_mask` is NOT needed per shard. That helper
  (openfhe_lib.cxx:108) is the SIHE Chebyshev-relu windowed-constant primitive
  the graph emits for relu value-range control; it has nothing to do with
  input sharding.

### No regression of the passing single-shard cases

The passing generated graphs all use a single whole-image shard:
`{NORMAL, 0, 0, 0, 0}` with `scheme->_count == 1` (e.g. the `add` cases and a
`:sharding` stride-conv that PASSes both have `desc_0 = {NORMAL,0,0,0,0}`,
`scheme_0._count = 1`).

For these, `scheme->_count == 1` and `desc[0]._count == 0`, so the rewrite's
loop runs once, takes the whole-image branch, encodes the whole tensor, and
calls `Io_set_input(name, 0, ct)` -- byte-for-byte the current behavior
(openfhe_lib.cxx:66-69). The loop also always iterates the scheme's shard
count (no `k>1` guard needed): for single-shard inputs it degenerates to
setting idx 0. This is the same property that makes ant's `Prepare_input`
(rtlib.c:164-192) correct for both single-shard and multi-shard cases. No
regression.

(One non-obvious invariant: `Io_init` already allocated `_count` slots per
name from `Get_encode_scheme(i)->_count` -- io_lib.c:72-73 -- and
`Io_set_input` bounds-checks `idx < _count` -- io_lib.c:33. So filling
0..count-1 is exactly the contract; the current code only happens to satisfy
it because count is 1 for the passing cases. For resnet18 the current code
fills only slot 0 and would later hit `IS_TRUE(data != nullptr)` in
`Get_input_data` (openfhe_lib.cxx:78) for idx 1..3 -- but it never gets there
because `MakeCKKSPackedPlaintext` throws first when the tensor exceeds the
slot count.)

## 6. regress58 catalog df default, and whether df-on is a workaround

The catalog entry (in `doc/regress58-params/regress58_catalog.csv`) for this
case is:

```
test_conv_f,conv/resnet18-conv2d_1x16x28x28_28_14_7.onnx,
-VEC:ms=4096:sharding -CKKS:q0=60:sf=59:N=8192,cti-param,conv,resnet18-conv2d_1x16x28x28_28_14_7
```

There is NO `-P2C:df=` in the optset, so regress58 exercises this case with
**df OFF** by default.

Enabling df in the catalog would **not** be a workaround:
1. df-on does not build on the OpenFHE backend (`Pt_from_msg` undeclared,
   section 3), so the run would fail at compile, not pass.
2. Even if df-on built, `main.c` still calls `Prepare_input` once
   (`onnx2c.py:339` has no df branch), so it would still hit the same
   non-sharding `Prepare_input` and crash at the oversized
   `MakeCKKSPackedPlaintext` call.
3. df does not change `Get_encode_scheme` or the graph's input-read loop, so
   the backend still needs to shard the single whole-tensor `Prepare_input`
   call into per-shard ciphertexts.

Therefore the catalog failure is the df-off path, and the proper fix is the
`Prepare_input` sharding edit in section 5 (mirror ant rtlib.c:164-192).
Turning on df is not desirable as a workaround: it would neither build nor
avoid the sharding gap, and it would mask a backend feature gap that ant (and
rtlib-py) already implement. The catalog should stay df-off for this case;
the backend should be fixed.
